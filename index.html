Module 0015 min

Start here

Scraping means getting a computer to read a website and write what it finds into a spreadsheet, so you don't have to copy it by hand. You will not write code in this course. Claude writes it. Your job is the part Claude can't do well alone: deciding what to collect, spotting when the data is wrong, and knowing when to stop.

Websites range from easy to off-limits. This course uses IMD's own warning colours as a difficulty scale, so you can place any new site on it within a few minutes.

Green

The data is on the page

A table you can see, select and copy. Claude can usually read it directly.

IMD climate tables (Module 04)

Yellow

The data loads after the page

The page fills itself in from a hidden data feed. You find the feed, then collect from it.

IMD city weather (Modules 05–06)

Orange

The site has rules and traps

Pages of results, filters, rate limits, session memory or misleading errors. Collectable, with care.

IMD session behaviour; CCAC resource library

Red

Stop and ask

Logins, CAPTCHAs, paywalls, personal data, or terms that forbid it. Request the data instead.

Official IMD station records (Module 01)

The worked example

city.imd.gov.in/citywx/responsive shows, for each IMD station, the last 24 hours (max and min temperature, rainfall, humidity) and a 7-day forecast with warnings. A left-hand menu lists stations by state. Open it in a new tab now and keep it open.

Check your answer

Each station shows a "Past 24 Hours" panel (maximum and minimum temperature with departure from normal, rainfall, and relative humidity at 08:30 and 17:30 IST), sunrise, sunset, moonrise and moonset, and a 7-day forecast with temperatures, humidity, a short description and a colour-coded warning for each day.

Many smaller stations show blanks for some of these. That's normal, and Module 07 deals with it.

Module 0120 min

Should you scrape at all?

Ask these four questions before you collect anything. If any answer worries you, talk to your team lead first, and take legal or contractual questions to the relevant internal team.

  1. Is there an official route? A download button, an open-data portal, an API, or a data request process. Official data comes with documentation and is easier to defend in a publication.
  2. What do the site's terms say? Look for "terms of use", "copyright policy" or "data policy" links in the footer. Also open /robots.txt on the site. A missing robots file does not mean permission.
  3. Is any of it personal data? Names, phone numbers, addresses of individuals. If so, stop and check with your team lead.
  4. Could your collecting harm the site? Thousands of rapid requests can slow a government server for everyone. Module 06 covers pacing.
IMD in practice
  • On 12 October 2026, city.imd.gov.in/robots.txt returned a "not found" page, so the site states no crawling rules there.
  • IMD supplies historical station data on request. The procedure published by its Regional Meteorological Centre in New Delhi says the data is chargeable, that it is "only meant for the purpose mentioned in their request letter", and that it must not be passed on to other users.
  • So the scraped city page is fine for current conditions and forecasts, and for building your own daily record. For a long, publication-grade history of observations, the official request is the better source.
Try it · robots.txt
Open [site]/robots.txt for these two sites: [site 1], [site 2].
For each, tell me in plain English: does the file exist; which parts of the site it asks automated tools to avoid; whether it sets a delay between requests; and whether the pages I need are affected. Then find each site's terms of use or data policy page and tell me what it says about copying or reusing data, quoting the exact sentence.
On other sitesLook for the official route first, every time. Scraping is the fallback when no download exists or when the official route is too slow for the decision you need to make.
Check your answer

A good answer names a specific route, not just "the website": for example, a downloadable file on the agency's site, an open-data portal, a documented API, or a written data request to the agency. For IMD's historical station data, the route is a data request to a Regional Meteorological Centre (chargeable, and limited to the stated purpose).

If you can't find an official route for your dataset, write that down too. It's the reason you're scraping.

Module 0225 min

How web pages carry data

Every page reaches you in one of two ways, and the difference decides your whole approach.

TypeWhat happensHow to tellIMD example
StaticThe server sends the finished page with the numbers already in it.Right-click → View page source. Press Ctrl+F and search for a number you can see on screen. It's there.Climate page for a station: …/citywx/extreme/climate.php?id=42182
DynamicThe server sends an empty shell. Code in the page then asks a hidden data feed for the numbers and draws them.The number you can see is not in the page source.The main city weather page
Try the source test on IMD
  1. On the city weather page, note today's maximum temperature for New Delhi-Safdarjung.
  2. Right-click → View page source. Search for that number. It isn't there. The source is a page titled "Local Weather Report" with almost nothing in it.
  3. Now open the Safdarjung climate page, view source, and search for "1991-2020". It's there, in a plain HTML table.

This is why an AI tool that "reads" a web page can come back with nothing. When we asked Claude's basic web reader to describe the city weather page, it reported a title and no data. It hadn't failed. The data simply isn't in the page it received.

What the site says back

Every reply from a website carries a three-digit status code. You'll see them in the Network tab (Module 05), in Colab messages and in Claude's reports. Five are worth knowing.

CodeMeansWhat to do
200OK, here's the replyStill check the reply itself: IMD answers some requests for missing stations with an error message inside a normal reply
301 / 302Moved; go to this other addressCheck where you ended up. A redirect to the home page can mean your filters were dropped
403ForbiddenThe site refuses this request. Stop and see Troubleshooting
404Not foundWrong address, or the page was removed
429Too many requestsYou went too fast. Stop, wait, slow down
On other sitesRun the source test first on any new site. It takes 30 seconds and tells you whether you're at green or yellow.
Check your answer
  • City weather page: dynamic. The source is a short page titled "Local Weather Report" with no temperatures in it.
  • Climate page: static. Searching the source for "1991-2020" finds it, and the monthly figures sit in a <table>. For Safdarjung, the January row reads 7.5, 20.1, 19.2, 1.7, 0.2, 1.4, 21.6, 0.1.
  • Your own site: either answer is fine, as long as you checked a number you could see on screen.
Module 0325 min

Recon before you collect

Before anyone writes code, map the site. You want to know what exists, how it's organised, how many items there are, and how you'd know if you'd missed some. Ask Claude to do this with you, and tell it explicitly not to extract anything yet.

Prompt · recon
Open [URL] in your browser. Don't extract any data yet. I want a map of the site:
1. What data is shown, and for what units (cities, stations, documents, dates)?
2. How is it organised? Menus, filters, pages of results, search?
3. Roughly how many items are there in total, and how did you count them?
4. Is the data in the page source, or loaded afterwards from a data feed?
5. Is there a download button, open-data link, API page or terms of use?
Reply in plain English. I don't code.
What recon found on IMD (12 Oct 2026)
  • Stations are grouped under 35 state and UT headings, with 1,729 station entries in total.
  • Every station has a numeric ID. Safdarjung is 42182 and Port Blair is 43333.
  • Station names are not unique. 21 names appear more than once with different IDs, such as "Bilaspur" (Chhattisgarh and Himachal Pradesh) and "KATHUA" (twice in Jammu & Kashmir). Always keep the ID.
  • The site spells some states its own way ("Chhatisgarh", "Uttrakhand", "Orissa"), and some names carry trailing spaces. Expect to tidy these.
  • Each station's page links to a separate climate page (static), which is easier to collect.
On other sitesWrite down the total count at the start. It's your yardstick later: if the site says 1,729 and your spreadsheet has 1,602 rows, you know to investigate.
Check your answer
  • Count: 1,729 stations in 35 state and UT groups on 12 October 2026. The number may have changed since; what matters is that Claude explains how it counted. A count with no method is a guess.
  • IDs: numbers of 4 to 6 digits, such as 42182 (Safdarjung), 99405 (UJWA) and 101101.
  • Your state: the station count for your state should match the table under "Your state and progress", unless IMD has added stations.

Module 04Green30 min

Tables you can see

When the data sits in the page as a table, you have three easy routes. Use the simplest one that works.

  1. Copy and paste. Select the table, copy, and paste into Google Sheets. Fine for one page.
  2. Ask Claude to read it. Give Claude the link and ask for the table as CSV. Fine for a handful of pages.
  3. Pull it into Google Sheets with a formula. =IMPORTHTML("link", "table", 1) fetches the first table on a page, and changing the 1 to a 2 fetches the second. Useful when the same layout repeats across many links. Its cousin =IMPORTXML("link", "//td") pulls out any part of a page you can describe; ask Claude to write the second part for you.
IMD climate page

Each station's climate page has a predictable link: https://city.imd.gov.in/citywx/extreme/climate.php?id= followed by the station ID. It holds two tables:

  • Table 1: 15 years of monthly extremes for the current month (highest max, lowest min, heaviest 24-hour rainfall, monthly total), plus all-time records.
  • Table 2: the 1991–2020 climatological normals by month (mean temperatures, rainfall, rainy days, and days with hail, thunder, fog and squall).

Try =IMPORTHTML("https://city.imd.gov.in/citywx/extreme/climate.php?id=42182","table",2) in a blank Google Sheet. This route is unconfirmed: in our test on 12 October 2026, the formula showed #REF! when the sheet was read back, and we couldn't yet check it in a live browser. Some government sites block Google's servers. If you see an error, fall back to route 1 or 2, and tell the course owner what you saw.

Notice what the table is not telling you. On 12 October 2026 the Safdarjung table had an empty row for 2024. A blank is a gap in the source, not a zero.

Module 05Yellow40 min

Find the hidden data feed

Dynamic pages are usually easier to collect from than they look, because the hidden feed is already clean, structured data. You find it with the browser's own developer tools. You only need one panel.

  1. Open the IMD city weather page in Chrome or Edge.
  2. Press F12 (Mac: Cmd + Option + I). A panel opens.
  3. Click the Network tab, then the Fetch/XHR filter. This hides images and styling and shows only data requests.
  4. Click a station in the left menu, say Port Blair. New rows appear in the list.
  5. Click each new row and open its Response or Preview tab. You're looking for the one that contains the numbers you see on screen.
  6. On that row, the Headers tab shows the address and the method (GET or POST). The Payload tab shows what the page sent.

Tip: right-click the row and choose Copy › Copy as cURL. This copies the exact request as text. Paste it into Claude and ask "Explain this request in plain English: where it goes, what it sends, and which parts I'd change to get a different station." Check it for anything private before you paste: on sites where you're logged in, it can include your login details.

What the IMD page is doing
1 · Station listGET…/citywx/responsive/api/Returns every state with its station IDs and names.
→
2 · One stationPOST, form field ID = station ID…/api/fetchCity_static.phpReturns that station's observations, forecast and warnings.
→
3 · Climate linkInside the reply as extreme_url…/extreme/climate.php?id=The static page from Module 04.

The station reply has two parts. The first is today's record: max, min, rainfall, rh0830, rh1730, departures from normal, sunrise and sunset, a 7-day forecast and warning text. The second covers the past week with normal maximum and minimum temperatures (MAX_N, MIN_N) beside the actuals.

Orange trap. The station address does not change when you click a station, and adding ?ID=43333 to it does nothing. The server remembers which station your session last asked for. Open the address fresh in another browser and you get "Data will be uploaded shortly", which sounds like a delay but here means "no station chosen". You have to send the ID the way the page does, as a POST.

On other sitesDashboards, maps and "live" pages often work this way, including many air quality and power-sector dashboards. If the source test fails, go straight to the Network tab. When Claude can't reach a site from its own sandbox, ask it to use your browser instead.
Check your answer
  • Headers tab: Request URL https://city.imd.gov.in/citywx/responsive/api/fetchCity_static.php, Request Method POST.
  • Payload tab: one form field, ID, set to 43333 for Port Blair.
  • Response: starts with [{"station_id":"43333",… and includes "station":"Port Blair", "lat":"11.670000000" and "lon":"92.720000000".
  • Fields such as max, min and rainfall should match the Past 24 Hours panel for that day.

If you see two requests with the same name, the first (a GET, when the page loads) is for the default station. The one you want is the POST that appears when you click.

Module 06Yellow45 min

Collect: with Claude, or with a ready-made Colab notebook

Now you know where the data lives, collect it for every station in the state you claimed. There are two routes. Both run away from your computer: one in Claude's browser, one on Google's servers through Colab. Nothing is installed on your machine.

A good collection request spells out five things, whichever route you take: what to loop over, how fast, what counts as missing, how to check each reply, and what to produce.

Route A: Claude collects in its browser

Prompt · collect with Claude
Collect today's observations for every IMD station in [the state you claimed, spelled as the site spells it].
The station list comes from GET https://city.imd.gov.in/citywx/responsive/api/
Each station's data comes from POST .../api/fetchCity_static.php with form field ID=[station id].

Do this in your browser, on the IMD page. Rules:
1. Wait 2 seconds between requests.
2. Treat as missing (blank): empty, NA, (), 0000-00-00, and impossible values such as 99.9 °C or 999 % humidity.
3. Check each reply's station_id matches the ID you asked for. List failures separately, with IMD's message.
4. Keep station_id, station, page date, max_date, max, min, rainfall, rh0830, rh1730, updated time.
5. Give me the result as CSV text I can paste into Google Sheets, plus the failure list.
Before you start, tell me in plain English what you'll do and what could go wrong.

If Claude says the script timed out. Claude's browser tool stops a script after about 45 seconds, and a state with 20 or more stations at a 2-second pause takes longer. Ask Claude to "start the collection in the background, then check back until it has finished". This happened while building this course.

Route B: the IMD station collector notebook

Open the IMD station collector in Colab. Then run its six steps in order with the ▶ buttons. Change settings only in Step 1. To keep your own settings or changes, choose File › Save a copy in Drive first.

  • It collects today's observations, the 7-day forecast and the 14-day temperature table for each station, and optionally each station's climate page.
  • It waits at least 1 second between requests (2 by default) and stops after five failures in a row.
  • Placeholders become blanks, using physical limits for each kind of value, so a real 99 mm of rain is kept but a 99.9 °C temperature is not.
  • Stations with no data go on a no_record tab, and IMD's raw replies are kept on a raw_replies tab so every number can be traced.
  • The maximum temperature is stored with its own date (max_temp_date), not the page date.
  • Results go to a new Google Sheet, an Excel file in your Drive, or both.

Check the connection first. Step 3 tests whether Google's servers can reach IMD. The notebook was tested on 12 October 2026 against saved IMD replies, not yet from Colab against the live site. If Step 3 fails, use Route A and tell the course owner what the message said.

Safety. Only run notebooks from the course folder or ones Claude wrote for you in your own conversation, and read what each step says before you press ▶. Colab will ask for permission to use your Google account when saving; that's expected for Sheets and Drive, and nothing else.

On other sitesThe five-part request (loop, pace, missing values, checks, output) works for any site. Only the addresses and field names change. For a new site, ask Claude to write a Colab notebook with the same structure as the IMD one: settings, connection check, collect, check, save.
Check your answer

Live readings change every day, so check the shape of your result rather than the values:

  • One row per station that returned data, plus a list of stations that didn't. Rows plus failures should equal your state's station count. The notebook's Step 5 prints this check for you.
  • Every row has a station ID, and the ID matches the station name in the site's list.
  • Blanks where IMD sent a placeholder. No 999, 99.9, 99.0 or NA left in the file.
  • The maximum temperature's date is one day before the page date.
  • Some stations with most fields blank. On 12 October, 7 of Delhi's 17 responding stations had no maximum temperature. Your state will have its own share.
  • Notebook only: 7 forecast rows and 14 temperature-table rows for each station with a record.

Reference run, Delhi, 12 October 2026, 11:13 IST: 18 stations listed, 17 rows, 1 failure (UJWA, 99405).

Module 07Orange35 min

Clean and validate

A collector that runs without errors can still hand you wrong data. This module is where your research judgement matters most. Never let a scraped number into a CEEW output until you've done these checks.

What the Delhi run actually returned
  • 18 Delhi stations were listed. 17 returned a record. One (UJWA, ID 99405) returned "Data will be uploaded shortly".
  • Of the 17, seven had no maximum temperature at all. Many of the newer stations report only some fields.
  • Departure-from-normal fields used NA for missing, while the page's own code treats 99.9, 999 and 999.00 as missing too.
  • In Goa, five market-yard stations showed an update time of 0000-00-00 00:00:00, which is a placeholder, not a time.
  • Several Goa stations showed rainfall 0.00 with every other field missing. Is that a dry day or a default? The data can't tell you. Flag it rather than assume.
  • The record's max comes with its own max_date, which was 11 October on a page dated 12 October. Read the date attached to each value, not just the page date.

Five checks for any scrape

  1. Count. Does the number of rows match the count from recon? Explain every gap.
  2. Missing codes. Find the site's placeholders (999, -99, NA, 0000-00-00, "—") and turn them into blanks. Ask Claude to scan for values that repeat suspiciously.
  3. Range. Temperatures above 50 °C, negative rainfall, humidity over 100%. Flag, don't delete.
  4. Identity. Every row keyed on an ID, and the ID in the reply matches the ID you asked for. No duplicates.
  5. Spot-check. Pick five random rows and compare them by eye with the live page. Note that you did it, and when.
Prompt · validate a scrape
Here is my scraped CSV from [site], collected on [date]. Recon said there should be [N] items.
1. Compare the row count with [N] and list what's missing.
2. Find likely placeholder values (repeated 999s, NA, zero dates, suspicious zeros).
3. Flag out-of-range values for these fields: [field: plausible range].
4. Check for duplicate IDs and duplicate names with different IDs.
5. Pick 5 random rows and tell me exactly where on the live site to check each one.
Don't change the data. Give me a list of issues and a suggested fix for each.

Module 0830 min

Repeat, pace and document

The IMD city page only shows today and the past week. If you need a season of daily readings, you have to collect every day and keep adding to one file. That raises three questions: how to repeat it, how to stay polite, and how someone else picks it up.

Repeat

  • Google Sheets on a timer. Track B lesson B3 gives you an Apps Script that runs once a day on Google's servers and adds that day's rows to a Google Sheet. No computer needs to be on.
  • Claude on a schedule. Ask Claude to set up a scheduled task that repeats your Module 06 Route A request each day.
  • Collect at a fixed time each day, ideally after IMD's morning update. The updat field tells you when each station was last refreshed.
  • Keep a "collected_at" column so you can tell a missed day from a missing reading.

Keep the raw replies

Save what the site actually sent, untouched, beside your cleaned table. If someone later questions a number, or you find a cleaning mistake, you can redo the cleaning without collecting again, and IMD's page will have moved on by then. The collector notebook does this on its raw_replies tab.

Pace

  • One request every 2 seconds is a sensible default for a government site. All 1,729 IMD stations at that pace takes about an hour, so collect only the states you need.
  • Stop on errors. If replies suddenly go blank or return "too many requests", wait and slow down. On the CCAC resource library, rapid requests were blocked and some pages stayed locked for over half an hour.
  • Run long jobs outside working hours.

Document

Write a short scraping log the day you finish. Your future self, and anyone checking your numbers, will need it.

B3 · Daily collection with Google Sheets and Apps Script

IMD_daily_collector.gs runs once a day on Google's servers and adds that day's observations for your state to a Google Sheet. After a few weeks you have a history that IMD's page doesn't keep.

  1. Create a new Google Sheet. Choose Extensions › Apps Script.
  2. Delete what's there. Open IMD_daily_collector.gs on GitHub, choose Copy raw file (the copy icon), paste it in, and save. Set STATE to the state you claimed, spelled as IMD spells it.
  3. Choose testOnce in the function menu and press Run. Approve the permissions Google asks for. Check that rows appear on the observations tab.
  4. Choose installDailyTrigger and press Run once. It now runs every day around 11:00 IST. To stop it, run removeTriggers.

Apps Script stops any run after about 6 minutes. With the 2-second pause and IMD's reply time, that's roughly 70 to 120 stations, so it suits one state, not all of India. The script stops itself at 5 minutes, saves what it has, and notes how many stations it skipped. Running it twice on one day doesn't add duplicate rows.

Gotcha field guide

Traps from the IMD and CCAC work, each with the general rule it teaches.

"The AI says the page is empty"The data loads after the page.Run the source test; go to the Network tab.
Address never changesThe site keeps state on the server.IMD remembers your last station per session. Send what the page sends.
"Data will be uploaded shortly"Error messages can mislead.On IMD this appears for no session, a wrong ID and a silent station alike.
99.9 · 999 · NA · 0000-00-00Placeholders look like data.List the site's codes and blank them before any averaging.
Rainfall 0.00, everything else blankA zero may be a default.Flag zeros that arrive with no other readings.
Two "Bilaspur"sNames aren't identifiers.Key every row on the site's ID.
max_date ≠ page dateEach value has its own time.Store the date that travels with the value.
3,496 items when you filteredFilters can drop silently.On CCAC, check the item count on every page you collect.
"Too many requests"You went too fast.Slow down, wait, and don't retry the same page repeatedly.
Status 200 with {"status":404} insideA normal reply can carry an error.IMD does this for stations with no data. Check the content, not just the code.
Departure of 99.0Placeholders vary by field.Judge each value against what's physically possible for its kind.
No climate page linkNot every station has every product.Some IMD stations (Jafarpur, for one) have no climate page. Record it; don't guess the address.
Header rows vanishTools guess where headers end.While building the course notebook, skipping a fixed two rows silently dropped January and February. Pick data rows by what they contain.
